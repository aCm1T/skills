# Blackboard 课件下载

基于 [BB-BlackBoard-Content-Downloader](https://github.com/aCm1T/BB-BlackBoard-Content-Downloader) 完成用户指定范围的本地下载。保留课程目录和原始文件名（必要的文件系统字符替换除外）。

这里的整理是保留 Blackboard 的课程及栏目层级，并提供附件核验清单；不默认总结内容、按讲次重新分类或重命名。用户另有整理要求时，在保留原始附件和来源对应关系的前提下处理。

## 输入与范围

从用户提供的链接、上下文和当前页面确定 Blackboard 站点、课程/栏目、输出位置。只询问仍有歧义的必要信息。链接里的 `course_id`、`content_id` 是候选标识，需要当前 API 返回的标题和 ID 核对；课程显示编号与内部 `id` 不可混用。

仅下载用户指定范围。单个栏目不扩展为整门课，单门课不扩展为所有课程。打包、放到桌面、按栏目分包等仅在用户要求时执行。不要内置过去使用过的课程 ID、账户信息或输出目录。

## 准备与认证

需要 Python 3.10 或更高版本；首次准备需要网络以获取下载器及依赖，首次登录或会话真实失效时需要 Chrome/Edge 和图形界面，由用户完成校园登录及 MFA。下载器缺失时按运行指南准备一次，无需用户提前手动安装。

先读取 [运行指南](references/usage.md)。本地课件下载默认使用本 skill，不默认改为 computer use。下载器、依赖和登录缓存固定保存在跨任务共享缓存中，不随当前工作目录重新克隆、安装或登录。默认缓存根目录为 `$HOME/Documents/Codex/.cache/blackboard-downloader`，可用 `BB_DOWNLOADER_HOME` 覆盖；按站点 origin 隔离在 `sites/<site-key>/runtime/`。先检查此处的版本、依赖和缓存；仅缺失时准备一次。始终显式指定本次课件输出目录。不要向 skill 目录写入运行数据。

将 `BB_BASE_URL` 设置为目标站点根地址。若明确是 CUHK-Shenzhen Blackboard，可用 `https://bb.cuhk.edu.cn`；其他学校不得套用此地址。配置必须在导入上游 Python 模块之前完成。

使用上游 `get_session()` 验证缓存会话；无有效缓存时由用户在弹出的浏览器完成校园登录/MFA。不要索取或存储密码。Cookie 保存在该站点的固定 runtime 中；换课程或输出目录不清理缓存，不默认传入 `--relogin`。缓存目录权限 700、Cookie 权限 600（并先 `umask 077`），不打印内容、不加入交付物或版本控制。多站点使用不同副本，避免混用 Cookie。已有任务缓存仅在来源站点已核对且固定位置没有缓存时复制迁移，保留原件；不覆盖固定位置已有会话。真实会话过期仍需用户登录/MFA；网络或 TLS 故障应先诊断，不能直接断定为过期。

## 选择下载方式

- **整门课程**：先列出课程并核对名称、学期、内部 ID，再使用 CLI 的课程关键词选项或 `download_course()`。关键词可能匹配多个学期；没有匹配时 CLI 会退回交互选择，不代表成功。
- **指定栏目/内容页**：按运行指南获取目标内容对象，调用 `_process_content()` 仅处理该对象及子内容。此为上游私有接口，版本更新后先核对签名。
- **全部课程**：只有用户明确要求时才使用 `--all`。
- **更新**：上游只按文件大小跳过已有文件，不是哈希同步，也不会删除本地旧文件；有更新争议时重新下载到新目录比较，不覆盖唯一原件。

下载前记录可枚举的内容、附件 ID、原始文件名、大小和预期本地路径。预期数量以附件计，不以内容项计。递归分页枚举失败时标记覆盖范围未知，不能给出“全部完成”。

## 验证与交付

不要仅凭退出码、成功提示或 `files_failed == 0` 判断完整性。上游会吞掉部分枚举异常，并跳过未支持的内容类型。将枚举清单与实际文件逐项比对，核查同名文件、重试残留和因响应头产生的改名；输出清单记录每个附件的下载/跳过/失败/未支持状态、相对路径、大小和 SHA-256。

检查非空、已知大小和真实格式，排除伪装成附件的登录 HTML。PDF 可用 `pdfinfo`，ZIP/Office 文件检查 ZIP 完整性和相应文档结构；这些只是结构检查，不等于逐页内容审阅。缺工具时明确验证范围，不把未验证记为通过。

用户要求 ZIP 时，仅打包已核验的课件及非敏感清单；排除 Cookie、环境文件、虚拟环境和缓存。检查 ZIP 完整性及条目清单，避免覆盖已有同名包；另处复制交付物时比对 SHA-256。

报告已下载、已核验跳过、失败及未支持数量，提供输出路径。失败或枚举不全时明确标为部分完成，并列出具体缺口。网页正文、外部链接、嵌入视频和 LTI 内容不是这个附件下载器的完整覆盖范围；用户要求时再用当前可用的已认证浏览器处理，不能宣称附件下载等于整站归档。

## 故障处理

- 401：验证站点和会话，必要时重新登录一次；仍失败则报告阻塞，不循环重试登录。
- 403/404：上游可能返回空列表。用当前会话确认 HTTP 状态，区分权限不足、内容不存在和确实为空，不尝试绕过访问控制。
- 浏览器可访问但独立下载失败：浏览器登录不保证独立请求已认证；核验 downloader 会话。若 API 不开放，说明限制，按用户原范围考虑可用浏览器下载。
- 驱动缓存不可写：在工作目录设置 `SE_CACHE_PATH`，必要时用 `WDM_LOCAL=1`；不要为此修改系统目录权限。
- TLS：默认兼容模式仍验证证书；`BB_TLS_STRICT=1` 使用默认 TLS 设置。不得将关闭证书校验作为自动修复。
- 上游每个文件最多尝试 3 次；耗尽后记录失败，再针对原因修复，不无限重跑整个课程。
