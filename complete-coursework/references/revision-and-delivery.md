# 修订与交付核验

## 精简和局部修改

用户只要求找冗余时，先给具体位置、删改理由和必须保留的内容；用户授权精简后再修改。

常可压缩：重复题干、图表后原样重复的数值、等价参数的重复报告、函数名和代码输出列表、与题目无关的环境或复现教程。

通常必须保留：核心推导、估计对象、单位、有效性条件、影响模型的处理约定、独立样本说明、样本量歧义、判定与停止规则、让“最优或最小”成立的搜索依据。把说明移到其他文件前，先判断正文是否仍足以让阅卷人理解方法。

对于“只删这一段”“某题不改”“其余不变”：

1. 保存当前源码与成品快照，明确允许改动的段落或文件。
2. 检查必要说明是否已在别处存在，避免为删除重复文字又新增无关改动。
3. 用源码或抽取文本的差异确认改动边界；重编译后检查受影响页及分页。
4. 若版面预期不变，可对未改页做像素或内容比较；若自然重排，检查内容保真，不强求逐像素相同或页数相同。
5. 检查通过后更新正式副本，并核对多个交付副本的一致性。

## 文档与图表

- 依照作业和用户要求选择格式；公式较多时可用 LaTeX。不要为了沿用历史工具而忽略当前模板或用户偏好。
- PDF 编译成功不等于可用。重新打开最终文件，核对题号、公式、单位、身份字段和页码；渲染检查每页，检查字体缺失、溢出、遮挡、空白页和被裁切的内容。
- 编译警告是定位线索。修复实际的缺字和溢出，检查其他警告的影响，不能只因日志非空或页数变化就认定成品错误。
- 图中标签不能与坐标标题、数据或其他标签重叠；必要的初末均衡、曲线、面积和图注要明确。图和图注保持相邻，避免孤立图注跨页。
- 可打印文档检查字体嵌入与可读性；不要仅靠文本抽取宣布图表或版面正常。
- 只要后续修改会影响成品，重新检查该修改涉及的内容和版面；没有新问题时不反复无目的地扩大检查。

## 文件与打包

先区分题目必须提交的文件和可选工作资料。理论题无需额外提交代码；题目要求代码时提供可运行源码和依赖说明。可编辑报告源文件和图表按用户需要交付，不把临时渲染、缓存、密码或无关附件塞入代码包。

遵从规定的命名、目录层级和大小要求。按学号命名仅在该要求适用且身份已确认时采用；不能把历史学生或样例身份自动带进新文件。

核对最终交付版本：

- 文件存在、非空、格式能打开；要求的题号和小问全部覆盖。
- ZIP 通过完整性检查，条目与预期一致，没有危险的路径、重复条目或漏掉的输入和依赖。
- 包内源码与最终工作源码相符，明确禁止修改的文件与原始模板一致。
- 从最终 ZIP 在独立临时目录解压、构建或运行；不要误跑工作目录的旧源码，也不要依赖包外未声明的数据或绝对路径。
- 按算法性质核对结果：固定环境与确定性输出可逐字节比较；浮点或非确定性输出用有依据的容限、残差或统计标准。
- 重新编译可编辑报告包时，检查完整页面内容和图表。时间戳或压缩方式导致的 PDF 字节差异，不等于内容不一致。

## 可复用的文件完整性助手

[文件完整性助手](../scripts/verify_delivery.py) 只使用 Python 3.10 或更高版本的标准库。示例从作业目录运行，脚本路径按实际 skill 位置填写：

```sh
python path/to/skill/scripts/verify_delivery.py --root . \
  --file submission/solution.pdf \
  --zip submission/source.zip \
  --match 'submission/source.zip::solution.py=src/solution.py' \
  --report work/delivery-check.json
```

`--file`、`--zip`、`--match` 均可重复。所有本地文件路径相对于 `--root`；`--match` 左侧是 `ZIP::包内路径`，右侧是要比较的本地源码。`--report` 的父目录须已存在，报告不能覆盖被核验的文件；报告参数省略时只输出到终端。失败返回非零状态。

助手会检查所列文件、记录 SHA-256、检查 ZIP 路径和 CRC，以及指定包内文件与本地文件是否一致。它不执行代码，不验证 PDF 排版，也不能证明数学正确、身份命名正确或整体可提交。

## 交付表述

- 先说明已完成什么，再给实际最终文件链接和必要验证证据。
- 用户问“可以直接提交吗”时，依据当前证据给出判断；有未解决问题就指出影响，不能用“百分之百无误”或分数保证替代审查。
- 确认“准备好文件”与“已向平台提交”的状态。没有实际提交不能写成已提交。
- 若任务涉及分享或脱敏，检查正文、页眉页脚、文件名、文档属性、压缩包条目、批注、示例配置和日志；不要仅替换正文中的姓名。只交付授权范围内的资料。
