# 数值与程序作业

在题目确实包含数值或代码任务时使用相关部分；不要给纯理论题强加代码、实验或额外文件。

## 数学和统计计算

- 先从原题核对所有观测值、样本量、观察窗口和单位。样本和、数据长度等简单交叉检查能发现转录错误。
- 尽可能独立核算：精确分数或符号计算核对手算，数值残差或不变量核对矩阵与程序结果。不要只检查答案中是否出现了预期字符串。
- 先确定估计目标、采样单位和独立性，再选方差、标准误和置信区间。共享队列或同一天的数据可能相关，不能把每个个体都当作独立重复实验。
- 区分标准差与方差、率与尺度、绝对与相对误差、单侧与双侧区间、总次数与追加次数。未知方差或渐近近似的适用条件应简短说明。
- 拟合后检验要使用相应的参考分布或校准方法；不要把参数已知的检验直接套到参数由同一份数据估计的情形。
- 似然的支持集约束、参数边界和会改变估计存在性的退化情形不能漏掉。补充讨论只保留实际影响本题答案的部分。
- 相关性、有限样本达标和总体保证不是同一件事；模型给出的条件性结果不能扩大为普遍保证。

## 随机模拟

在写代码之前明确会影响结果的约定，并在正文保留必要的方法说明：

- 初始状态、预热、观察期、停止接收时刻及是否排空剩余任务。
- 同时事件的处理顺序、队列规则、容量是否含服务中的个体。
- 事件时间排序、转入下游的顺序和统计口径。
- 分布可能产生无效值时采用的处理方式；重抽、截断和取绝对值会改变不同的分布，不可默默替换。
- 原题要求的独立实验、不同小问之间的样本关系和共同随机数设计。需要新独立样本的地方不能复用已有样本。
- 观测窗口与最后一次观测不同。不能为了方便把题目给定窗口换成样本最大值。
- 置信水平、判定标准和停止规则。多次查看结果、搜索配置或筛选最优方案可能影响覆盖率，按实际方法解释。
- 枚举或优化声称的“最小”需要有搜索范围与排除证据。不要未经证明就假设复杂系统的性能单调。

将种子和随机流配置保存到代码或运行说明中以便复现，但不要把每道题都写成冗长的代码介绍。结果表、图和正文数值尽量从同一份运行输出生成，避免手动抄写不一致。

## 程序实现与模板

- 先识别允许修改的文件、函数签名、接口和禁止修改的驱动或测试文件。对受保护文件记录基线哈希，完成后与原始模板比较。
- 使用项目已有环境；缺少依赖时定位可用环境或补齐任务确实需要的依赖，不写死另一台机器的解释器路径。
- 正确性测试应覆盖真实风险：小尺寸或可手算例子、边界尺寸、非整除尾块、交换或重排、奇异输入、合法的空输入等。只测适用于该算法的情形。
- 数值算法用残差、合理误差容限或独立基准，而不是一律要求浮点结果逐位相同。必要时使用内存和未定义行为检查。
- 报告必须对应最终源码。修改默认参数后，确认实测时的显式参数与报告仍一致；保留历史测量的真实配置，不回写日志来制造一致。

## 性能与远程实验

- 实测记录保留输入规模、线程数、编译与优化选项、硬件或运行环境、重复次数和原始时间。比较要保持关键条件一致。
- 从原始记录重新计算吞吐量、加速比、中位数或其他汇总，核对公式和计量单位。不要把未运行的配置写成测量结果。
- 先确保正确性，再解释性能；只有任务有需要时才扩大测试或调参，不把一次历史作业的测试数量变成固定门槛。
- 只有本机运行就说明是本机；仅审查历史集群日志就说明是日志审查。必要实验暂不可运行时交付已完成部分和准确缺口，不伪造硬件、作业编号、日志或统计量。
- 远程上传、资源使用与登录依照当前会话的授权范围；授权缺失时准备好可在本地完成的实现和实验方案，避免反复询问已授权事项。
